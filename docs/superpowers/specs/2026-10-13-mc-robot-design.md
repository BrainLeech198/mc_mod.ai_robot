# mc_robot 设计文档

日期：2026-10-13
状态：待审阅

## 0. 目标

在本工作区搭建「AI 模拟 Minecraft 玩家进服工作」的系统：AI 以**真实可见玩家**身份进入「野粽乡」建筑服，用 WorldEdit 盖房子、协助管理。指令入口阶段一为 Claude Code 对话，阶段二扩展游戏内聊天。

成功标准：
1. AI 进服后其他玩家可见（有 ID、皮肤、可对话）
2. 说「盖个两层小木屋」，AI 在指定建造区内用 WE 完成，可撤回
3. 越界、危险操作被**强制**拦下，不靠自觉
4. `version/` 工作包让 AI 一进来马上能工作

## 1. 操作安全规范（硬约束）

> 本章优先级最高。任何实现、任何 AI 决策不得违反。违规即为 bug。

### A. 作业范围
1. AI 只能在 `workspace.json` 定义的**建造区坐标边界**内操作，越界一律拒绝执行
2. 任何 WE 操作前必须确认区域内无他人建筑/他人改动（本阶段：建造区为 AI 专用，白名单坐标是唯一准绳）
3. 禁止危险全局指令：超大半径 `//set`、`//drain`、`//regen`、`//limit` 之上的规模操作

### B. 撤回纪律
4. 每次开工前打检查点；操作批次异常立即撤
5. `//undo` 前必须确认当前改动是 AI 自己刚做的，绝不回滚他人成果
6. WE 撤回历史上限 10 次（WE 自身限制）；剩余 ≤2 次时停手上报，不再批量改

### C. 执行与留痕
7. 每条 WE 指令先写日志再执行（谁、何时、选区、指令、结果）
8. 危险指令（删除/大范围替换）需二次确认：阶段一由用户在 Claude Code 确认
9. 出错/断线/撤回失败：立即停止建造，报告状态，不擅自重做

### D. 账号与权限
10. AI 用独立游戏名，权限走 `ai_builder` 组（最小够用）；管理操作走单独流程，不混入建造通道

## 2. 总体架构

```
用户（Claude Code 下指令）
      ↓ 本地 HTTP + WebSocket
mc_robot 编排层（本仓库）
      ↓
ControlMod（Forge 1.20.1 客户端模组，仅本地）
      ↓ 游戏 API + WorldEdit API
真实 Forge 客户端（野粽乡全套 mod + AI 账号，真人可见）
      ↓
建筑服（简幻欢，1.20.1 Forge，创造服，离线登录）
```

- ControlMod **只跑在客户端**，不改服务端
- 阶段二扩展：游戏内聊天 → 同一编排层入口

### 为什么不是协议 bot

服务器强制客户端安装 mod 包，mineflayer 这类协议库无法通过 Forge 握手；且需求要求「真人可见」。真客户端 + 控制模组是唯一同时满足「进得去、看得见、用得了 WE」的路线。

## 3. version/ 工作包结构

设计目标：**AI 一进来马上能工作**，不现配。

```
version/
  1.20.1-forge/
    ready.json          # 就绪标记与校验清单
    config.json         # 服务器地址/端口/AI 账号/登录密码/门禁密码
    workspace.json      # 建造区坐标边界（双层防护第 2 层依据）
    mods.md             # 指向 yztc mod 清单的说明（jar 不重复入库）
    schematics/         # .schem 蓝图（用户放置；AI 也可自行导出）
    undo-policy.json    # 撤回策略（上限 10，接近上限停手阈值 = 2）
    runtime.json        # Java 路径、客户端实例目录、内存
```

不预置材质表/操作序列：方块 ID 与建造步骤由 AI 现场判断，写死反而限制发挥。`schematics/` 只存真正的蓝图文件。

新增 MC 版本 = 复制目录改配置。编排层按版本选目录启动。

## 4. 双层防护

服务器现状：全图自由建造、无保护插件。方案：

| 层 | 手段 | 作用 |
|----|------|------|
| 1. 服务端强制 | **Open Parties and Claims (OPAC)** `forge-1.20.1-0.32.7` | 圈「AI 建造区」，AI 越界物理上改不动 |
| 2. AI 自律 | ControlMod + 第 1 章规范 | 越界拒绝执行、二次确认、日志 |

- **只圈 AI 建造区**：全图默认自由建造，玩家不受影响
- OPAC 与已装 Xaero 小地图/世界地图原生集成，领地边界地图可见
- 用户负责加装 OPAC（Modrinth：https://modrinth.com/mod/open-parties-and-claims）
- 防护两层独立：bot 出 bug 时服务端仍兜底

## 5. ControlMod（客户端模组）

职责（单一）：把编排层的指令翻译成游戏内动作，把游戏状态回传。

接口（本地 HTTP + WebSocket）：
- 下行：执行 WE 指令、发聊天、移动/视角、登录指令、检查点/撤回
- 上行：聊天栏文本、玩家位置/朝向、选区、执行结果、错误

内部要点：
- 调 **WorldEdit Java API**（不走聊天栏发指令，更稳）
- 维护撤回记账（与 WE 历史对齐，上限 10，剩 2 停手）
- 拦截层：越界/黑名单指令直接拒绝并回报原因
- 登录自动化：识别 `yzt_super` 提示 → `/yzts gate|register|login`（含失败锁定/限频退避）

## 6. 编排层（本仓库）

- 读取 `version/<ver>/` 工作包 → 连 ControlMod → 自动登录 → 进入待命
- 接收用户意图（阶段一：Claude Code；阶段二：游戏内聊天）
- 生成「WE 操作序列」→ 分批下发 → 收结果反馈
- 危险操作暂停，等用户确认
- 全程日志

## 7. 建造流程（WorldEdit）

1. 用户描述需求（如「两层小木屋」）
2. AI 拆解为分层步骤：地基 → 墙体 → 屋顶 → 内饰
3. 每层 = 一批 WE 操作（选区 + `//set|//copy|//paste|…`），方块与步骤由 AI 现场定，`schematics/` 有蓝图则用
4. 层间打检查点；异常/用户不满意 → `//undo`（确认是 AI 自己的改动才撤）
5. 交付：报告坐标、用料、剩余撤回次数

## 8. 登录自动化（yzt_super）

| 场景 | 指令 |
|------|------|
| 全服门禁 | `/yzts gate <门禁密码>` |
| 首次进服 | `/yzts register <密码>` |
| 之后进服 | `/yzts login <密码>` |

处理 `login_bad`（退避重试）、`login_locked`（停手上报）、`login_rate_limited`（等待）。密码存 `config.json`，该文件加入 `.gitignore`，不进 git。

## 9. 错误处理

| 情况 | 行为 |
|------|------|
| 连不上服 / 握手失败 | 报告，不重试轰炸 |
| 登录失败锁定/限频 | 停手上报 |
| WE 越界 / 拒绝执行 | 拒绝 + 原因回报 |
| 撤回失败 / 断线 | 停止建造，报告状态 |
| 撤回剩余 ≤2 | 停手上报 |

## 10. 阶段规划

- **阶段一（本设计范围）**：真客户端 + ControlMod + 编排层 + WE 建造 + 登录自动化 + 双层防护落地
- **阶段二**：游戏内聊天指挥（同一编排层加输入源）
- **阶段三（可选）**：服务器管理能力（独立流程，独立权限）

## 11. 测试

- ControlMod：越界拦截、黑名单指令拦截、撤回记账（剩 2 停手）单测
- 登录流程：对 `yzt_super` 提示文案的识别与退避策略
- 建造流程：小样板（地基→墙→屋顶）在测试服/单机验证，撤回路径必测
- 手工验收：AI 进服真人可见、盖一栋小房子、越界建不动
