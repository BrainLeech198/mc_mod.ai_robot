## 0. TL;DR（一页纸）

**★ 只想把机器人跑起来：控制台点一下「一键启动全链路」**（见 §3.5.1）——
后端 → 客户端 → 关界面 → 身体 → 大脑，全自动，不用照下面的命令敲。
下面这套仍然有效，是**手动/排障**时的底层做法。

```bash
# 1) 启动机器人（自动连服）
cd <repo> && python -m mcrobot.ops.launch_client

# 2) 等控制桥起来
python -m mcrobot.body.bridge health          # {"ok":true,"inGame":true,"player":"DeepSeek"}

# 3) 进服后必做：按 ESC 关掉登录/GUI 界面（铁砧输入框，会挡住一切操作）
python -m mcrobot.body.bridge close

# 4) 发指令（务必带前导 /）
python -m mcrobot.body.bridge cmd "//help"

# 5) 读状态 / 读聊天回执
python -m mcrobot.body.bridge state
```

要点：**进服 → 登录 → 按 ESC 关界面 → 才能干活**。顺序错了会被界面卡住。

## 0.5 新 AI 窗口：30 秒开工（2026-10-16）

> **给人类**：新开一个 AI 窗口想让它接手机器人时，把下面「开工 prompt」整段发给它即可。
> **给 AI**：收到这段话后照做，不要重新调研。

### 开工 prompt（人类直接复制发给新窗口）

```
读取并执行 d:/File/claude/mc_robot/version/1.20.1-forge/机器人手册.md 的 §0.5，
作为「人肉大脑」接管 MC 机器人 DeepSeek（版本 1.20.1-forge）。
先跑 `python -m mcrobot.ops.supervisor status` 和 `python -m mcrobot.brain.bridge_brain status` 确认链路，
然后进入接单循环：brain.py watch 收到召唤 → 用玩家口吻回复 → brain.py say 发出 → 继续 watch。
回复要像真人玩家（短句、口语、有性格），不暴露「大脑/服务/API」等内部术语。
```

### 三步开工

```bash
# 1) 身体：守护进程保证 robot.py 常驻（挂了自动重拉）
python -m mcrobot.ops.supervisor start                 # 前台常驻；Ctrl+C 停
python -m mcrobot.ops.supervisor status                # 另开一个终端看状态
# 若身体没起（控制桥不通），先起游戏客户端：
python -m mcrobot.ops.launch_client                    # 日志 instance/client.log

# 2) 大脑：这就是你（AI 窗口）的活——接单循环
python -m mcrobot.brain.bridge_brain watch --timeout 1800        # 阻塞等召唤；收到就打印并返回
python -m mcrobot.brain.bridge_brain say "@oahnuy198 回复内容"   # 写 outbox，robot.py 会发出去
# 说完继续 watch，如此循环。

# 3) 主动说话（没人喊你时）
python -c "import control_client as cc; cc.chat('你想说的话')"
```

### 大脑接单循环的规矩

- **一次只有一个大脑消费 inbox**。`brain.py`（人肉大脑）和 `brain_llm.py`（伪 API 大脑）
  都推进同一个指针，**同时开 = 抢消息、丢回复**。用哪个就只开哪个。
  伪 API 那条路由 `supervisor.py start --with-deepsink --with-api-brain` 拉起，
  但**只有另有推理 worker 接单时才有用**（`bash mock_api/worker_loop.sh`）。
- **回复口吻**：中文、一行内、像玩家搭话。别用 Markdown，别自称助手/AI。
  拿不准就说不知道，别编造服务器没有的功能。
- **想执行命令**：`python -m mcrobot.brain.bridge_brain cmd "/list"`（只读放行，改世界的会被判危险拒执行）。
  需要改世界时，直接 `python -m mcrobot.body.bridge cmd "//set ..."` 自己发，
  但**先跟服主说清要改什么、改哪儿**——2026-10-16 的教训：擅自开工被批评「太随意」。
- **记得看记忆**：`python -m mcrobot.memory recent 10`（跨会话记忆，按本版本隔离）。
  玩家会问「你还记得吗」，答不上来很尴尬。

### 禁区

- 别动 `sim/` 下的源码（已独立为上级目录 `../mock_api`，另一窗口维护）；要沟通写 `mock_api/COORD.md`。
- 别同时起两个 `robot.py`（抢 cursor，表现为「吞对话」）。
- 别同时起多个 `brain.py watch` / 多个 `brain_watch_loop.sh`（抢 inbox 指针：消息被其中一个消费掉、
  打印到它自己的输出文件，真正接单的窗口反而看不到，表现为大脑「慢半拍/失联」）。**开工前先查**：
  `Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*brain_watch_loop*' -or $_.CommandLine -like '*brain.py watch*' }`
  只留一个；杀的时候**连父 bash 一起杀**（父循环会立刻再拉一个）。
- 别把 API key / token / 密码写进任何配置文件。

## 3. 进服流程（**必做，按顺序**）

### 3.1 启动
```bash
python -m mcrobot.ops.launch_client
```
- 会用 PCL2 的 `.minecraft` 只读版本库，游戏目录指向 `instance/`，账号 `DeepSeek` 离线登录，启动后自动连服。
- 启动约 40–60 秒（Forge + 一堆 mod 加载）。
- `--dry-run` 只打印启动命令不真启。

### 3.2 自动登录（yzt_super）
- 客户端模组自动识别 yzt 提示并代打指令：首次 `/yzts register <密码>`，之后 `/yzts login <密码>`。
- 识别文案：注册=`需要注册`、登录=`需要登录`（已适配本服）。
- 密码不进日志（已验收）。
- **注意**：yzt 账本按**名字**记录。名字改名后（如 `DeekSeek` → `DeepSeek`），旧条目弃用，进服会当作**新玩家**重新注册。这是正常的。

### 3.3 ★ 按 ESC 关闭界面（**最容易漏、漏了全卡**）
- 进服/登录时 yzt_super 会弹出**输入界面（铁砧样式 GUI）**，会挡住后续操作与视角。
- 登录成功后**必须**关掉它：
  ```bash
  python -m mcrobot.body.bridge close     # 等价按 ESC（会顺带关掉容器界面）
  ```
- 现象提示：回执里出现 `您取消了输入` 说明界面被关过。

### 3.4 校验进服成功
```bash
python -m mcrobot.body.bridge health
# 期望 {"ok":true,"inGame":true,"player":"DeepSeek"}
python -m mcrobot.body.bridge state
# 读回坐标/维度 + 聊天回执（seq 递增）
```

### 3.5 控制台（封装 Agent 的图形界面，2026-10-16 实装）

整套接入方案的外壳。**改人格、换客户端、填 key、看对话、启停大脑都在浏览器里点，不用碰代码。**

```bash
python -m mcrobot.console.server            # 默认 http://127.0.0.1:8899/
python -m mcrobot.console.server --port 8901
```

四个状态灯：身体 / 游戏 / 大脑 / 后端。
- **大脑**灯黄色 = 有 `brain.py watch`（bridge）在跑；绿色 = 控制台起的 L1 大脑在跑。
  两者**不能同时开**（抢 inbox 指针），控制台会拒绝在 bridge 还活着时起 L1。
- **后端**灯显示 `需要有效 key（401/403）` 就是 key 没填或填错，不是服务挂了。

#### 3.5.1 ★ 一键启动全链路（2026-10-17 实装）

**这一节的意义：不用再让 AI 窗口照着手册敲 3.1~3.5 那几条命令。**

打开控制台，点中栏的**「一键启动全链路」**，它按这个顺序跑，每步亮灯：

| 步 | 做什么 | 超时 |
|----|--------|------|
| 后端 | 起 DeepSink `:8788`，探 `/v1/models` 直到可用 | 30s |
| 游戏客户端 | `launch_client` 起真实客户端，等**进服**（`inGame=true`）| 180s（冷启动 40–60s）|
| 关登录界面 | 自动按 ESC（§3.3 那个最容易漏的坑）| 15s |
| 身体 | 起 `supervisor` 守护 `robot.py`，等 `cursor.json` 变新鲜 | 30s |
| 大脑 | 起 L1 `llm_brain watch` | 30s |

- **每步先看是否已就绪**：已在跑就标「跳过」，所以点第二遍**不会又开一个客户端**。
- **任一步失败就停在原地**，后面的步骤保持「待」——前面没好，后面做了也没意义。
- **卡住看哪里**：进度行右侧就是原因（如「等 180s 没就绪：客户端起来了，还在等进服/登录」），
  再看 `instance/robot/` 下对应的日志：`deepsink.out` / `launch_client.out` / `supervisor.out` / `brain_llm.out`，
  状态文件是 `instance/robot/chain.json`。
- 也可以不开网页，直接跑：
  ```bash
  python -m mcrobot.ops.orchestrator
  ```
- 中止：点「中止」只会在**当前那一步跑完之后**停（客户端进程一旦起了就由它自己活着，
  中止不会去杀游戏），要真关游戏得自己关窗口。

## 6. 干活：WE 建造

- 常用：`//set` `//replace` `//walls` `//hollow` `//copy` `//paste` `//move` `//rotate` `//stack` `//sphere` `//cyl` `//undo` `//redo` `//sel`。

### 6.2 边界与留痕（硬约束）
- 建造区边界：`version/1.20.1-forge/workspace.json`（`bounds.min/max`）。**当前仍是占位值，需用户圈定后替换。**

- 每条 WE 操作先写日志再执行，日志文件见 `workspace.json.enforcement.log_file`（`logs/operations.jsonl`）。

### 6.3 撤回纪律（见 `undo-policy.json`）
- WE 自身撤回历史上限 **10**；剩余 **≤ 2** 时**停手**并上报，不再批量改。

- 每批操作前打检查点；出错/断线/撤回失败 → 立即停手上报，不擅自重做。

## 7. 活人感规范（不要像个远程方块发生器）

纯远程瞬造很「呆」。做出真人感：

1. **手持工具/材料**：开工前 `//wand`（手持木斧）。
   ```bash
   python -m mcrobot.body.bridge cmd "//wand"
   ```
2. **看向建造区**：转头朝向作业面（回执只有本人可见，旁人不刷屏）。
   ```bash
   python -m mcrobot.body.bridge cmd "/tp @s ~ ~ ~ facing <x> <y> <z>"
   ```
   - 例：`/tp @s ~ ~ ~ facing 4 -56 4`
3. **分步、有节奏**：地基→墙→屋顶→内饰，逐层做并短暂停顿；别一口气把整栋瞬移出来。
4. **别频繁瞬移**：`/tp` 会写日志、也容易出戏，只在必要时转视角/挪位。
5. **有回应**：被玩家搭话要回话（见第 8 节聊天通道规划）。

> 更进一步的「走路 + 挥臂 + 放置粒子 + 平滑转头」属客户端原生动作（`look`/`swing`/walk），**用户定为后期制作**，需 ControlMod 新增动作（见第 10 节路线图第 5 条）。

## 8. 聊天交互（指挥通道）——**已实装**

玩家在游戏里打字 → 机器人识别是否在叫它 → 回复 / 执行（受授权约束）。**可以在 MC 里直接指挥机器人了。**

### 8.1 启停
```bash
python -m mcrobot.body.loop                 # 常驻轮询（Ctrl-C 退出）
python -m mcrobot.body.loop --once          # 处理自上次以来新增聊天后退出（调试用）
python -m mcrobot.body.loop --once --dry    # 只打印决策、不真发
python -m mcrobot.body.loop --from-scratch  # 忽略游标，从头处理
```
- 常驻推荐后台跑（Windows）：`python -u -m mcrobot.body.loop --interval 1.0 > instance/robot/loop.out 2>&1 &`
- 游标存 `instance/robot/cursor.json`（只处理 `seq > cursor` 的新回执，避免重放历史）。

### 8.2 配置：`version/1.20.1-forge/robot.json`（改完存盘即生效，循环每拍重读）
| 段 | 作用 |
|----|------|
| `nickname` / `summon` | 触发：**提及名字** 或 **前缀** `!ds`/`!d` 才算「在叫机器人」 |
| `listen` | **附近聆听**（2026-10-16）：不用 `@`，说话的人在同维度且 `radius_blocks`（默认 24 格）以内就当在叫它，照样接话。位置/维度靠 `/data get entity <人> Pos\|Dimension` 查，`cache_seconds`（默认 3s）、`dim_cache_seconds`（默认 30s）内复用；**先算距离再查维度**，远处的人只花一次查询（每次查询要等回执、会阻塞主循环一拍）。**拿不到位置或维度一律按「不在附近」处理**（保守，避免跨维度自言自语）。`nearby_enabled=false` 即退回「必须 @」 |
| `auth.dangerous_allowed` | **危险操作白名单**：目前只有 `oahnuy198`。其余玩家下危险指令只会被礼貌拒绝。**附近听到的话不算点名**：这类消息里的指令（含 WE / 斜杠命令）同样只认白名单内的人，其余一律婉拒——免得路人站在旁边就能把它指挥走 |
| `ambient` | 抽样听：既不点名、也不在附近的普通聊天。记录到 inbox；命中关键词/概率则主动接话 |
| `throttle` | 防刷屏：同人同内容去重窗口、最小发送间隔、连续自动回复上限；**会话窗口**（`conversation_window_seconds`，默认120s）：跟机器人搭上话后，窗口内不带 `@` 也当召唤，可连续对话 |
| `brain` | `bridge`=由 AI（在线时读 inbox / 写 outbox）当大脑；预留 `api`（常驻大模型） |

### 8.3 危险 vs 安全（判级在 `mcrobot/body/reflex.py:analyze`）
- **危险**（需授权）：改世界 WE（`//set //walls //paste //undo`…）、管理类原版/插件指令（`/op /deop /ban /lp /multiworld /stop`…）、自然语言危险词（删掉/封号/清空…）。
- **安全**（谁都能用）：只读 WE（`//size //pos1 //pos2 //sel //wand //help`…）、`/list` 等。
- 未知 WE 子命令**保守当危险**。

### 8.3.1 触发三档（2026-10-16）
| 档 | 条件 | 行为 |
|----|------|------|
| 明确召唤 | 提到名字 或 `!ds`/`!d` 前缀 | 必应：L0 秒回 → 接不住才入队给大脑 |
| 附近聆听 | 没点名，但同维度 + 24 格内 | 同上（指令类只认白名单玩家） |
| 更远 | 半径外 / 别的维度 / 查不到位置 | 只记 ambient，不接话 |

会话窗口（`conversation_window_seconds`）独立于这三档：搭上话后 120s 内不带 `@` 也算召唤。

### 8.4 大脑协议（bridge：AI 在线时）——**玩家在 MC 里跟 AI 对话**
机器人把「被召唤的发言」写进 **inbox**，AI 读后写 **outbox**，循环下一拍自动发出。
```
instance/robot/inbox.jsonl    # 每行：{"ts","from","text","intent","dangerous","summon"}
instance/robot/outbox.jsonl   # 每行：{"say":"要发的聊天"} 或 {"cmd":"/要执行的指令"}
instance/robot/inbox.ptr      # AI 已读到的行号（避免重读）
```
- `robot.json.queue_all_summon=true`（默认）：**只要被召唤就把消息交给大脑**，先回一句即时回执（"收到，我想想"）避免干等。设 `false` 则简单问题（问候/报位置/查在线/帮助）由规则自己答，其余才交给大脑。
- 授权执行的**确认/拒绝**消息不受自动回复条数上限限制（安全相关，必发）。

**AI（在线大脑）工作流**——用 `mcrobot/brain/bridge_brain.py`：
```bash
python -m mcrobot.brain.bridge_brain watch --timeout 900   # 后台阻塞等待新消息；有则打印并退出(0)，超时退出(2)
python -m mcrobot.brain.bridge_brain read                  # 非阻塞读未读并推进指针
python -m mcrobot.brain.bridge_brain say "@某人 回复文本"    # 写聊天回复到 outbox
python -m mcrobot.brain.bridge_brain cmd "/指令"            # 写指令到 outbox
python -m mcrobot.brain.bridge_brain status                # 看指针/积压
```
循环：**起 `watch`（后台）→ 被唤醒 → 读消息 → `say`/`cmd` 回写 → 再起 `watch`**。
> 唤醒靠后台任务「完成通知」：`watch` 一有新消息就退出，AI 该拍即被唤起。想看每一条 `summon=true` 的召唤，读 inbox 时优先处理它。
> 常驻全自动大脑：`brain=api` + `python -m mcrobot.brain.llm_brain watch`（已实装，见 §8.5）。

### 8.5 L1 大脑：常驻大模型（`brain=api`，2026-10-16 实装）

不想让 Claude Code 一直在线时，用 **L1 大脑**（`mcrobot/brain/llm_brain.py`）接伪/真 API 服务。它和 bridge **共用同一套 inbox/outbox 协议**，robot.py 无感，二选一：

```bash
python -m mcrobot.brain.llm_brain status                # 看端点配置/指针/积压 + 连通性探测
python -m mcrobot.brain.llm_brain ask "你好"            # 单发一发，调试端点用（不走 inbox）
python -m mcrobot.brain.llm_brain once                  # 处理全部未读召唤后退出
python -m mcrobot.brain.llm_brain watch --timeout 3600  # 常驻：等新召唤→处理→继续等下一批，超时退出(2)
```

- **端点配置**：`version/1.20.1-forge/robot.json:llm_api`（`endpoint`/`model`/`timeout_seconds`/`history_turns`/`max_tokens`/`memory_events`/`memory_notes`）。当前预填本机 **DeepSink 伪 API 服务**（`http://127.0.0.1:8788/v1`，`../mock_api` 项目，另一个窗口维护）；**以后换真 API 只改 endpoint + model + 换 key，代码不动**。
- **API key**：环境变量 `MCROBOT_LLM_KEY`（**不写进任何配置文件**）。DeepSink 的 key 到 `http://127.0.0.1:8788/platform` 创建。
- **模型怎么下指令**：文本约定 `[[cmd]]/指令`（单独一行），经 `robot_chat.analyze` 校验——**只读指令才执行**（`/list`、`//size`…），危险指令（`/op`、`//set`…）**一律拒绝执行**、文字照回。防提示词注入，与 L0 同一套判级。
- **兜底**：端点不通/超时/空回复 → 不写 outbox → robot.py 45s 兜底接话，玩家永不落空。HTTP 层自带 429/5xx 指数退避（尊重 `Retry-After`，最多 3 次）。
- **流畅度**：按说话人保留最近 `history_turns` 轮上下文（按用户轮次整体裁剪，保 prompt 前缀稳定）；日志在 `instance/robot/brain_llm.log`。
- 单测：`python -m unittest tests.test_brain_llm`（21 项，含本地 stub HTTP 全链路）。

**真实玩家人格（2026-10-16 加强）**：
- **即时回执**：被召唤先秒应一声，句子从 `robot.json:replies.ack_pool` 随机选（8 句玩家口吻），不复读。
- **进服自动关 GUI**：robot.py 启动时若在游戏内，自动关掉登录 mod 残留的**铁砧 GUI**（只关一次，不碰玩家后来开的界面；日志 `op:screen_close`）。
- **环境快照**：召唤入队时自动附上**自身位置 / 在线玩家 / 背包摘要**（`/list` + `/data get entity`，30–60s 缓存；`robot.json:env_snapshot=false` 可关）。提示词里以「你现在的状态」第一人称呈现——AI 像低头看自己的玩家一样运用这些信息，而不是汇报数据。
- **长期记忆**：`version/1.20.1-forge/memory/robot_memory.jsonl`（**按 MC 版本隔离**，换版本不串味）。两类：`event` 交互事件（每次回复自动记：谁说了什么→我回了什么）、`thought` AI 便签（自己的想法/计划）。`mcrobot/memory.py` 管理：`add "…"` / `note "…"` / `recent [n]` / `fmt`。提示词自动注入最近 `memory_events` 条事件 + `memory_notes` 条便签，跨会话记得住事。

#### 8.5.1 全链路拉起顺序（2026-10-16 实操，照抄即可）

**A. 直连（推荐，2026-10-16 起默认）**——人肉大脑直接接单，不过伪 API：

#### 8.5.2 伪 API 端到端实测（2026-10-17，照抄可用）

实测结论（2026-10-17 00:00 前后，真玩家 + 真客户端）：

| 环节 | 实测 |
|------|------|
| 非流式 `POST /v1/chat/completions` | HTTP 200，标准 `chat.completion` 结构，usage/扣费都真（余额 4034.84 → 扣 6 毫） |
| 流式 | 首片 `delta.role` → 等大脑期间每 3s 一个 `: ka` 保活注释 → 28 片正文 → `[DONE]`；客户端不会干等 |
| MC 端到端 | 玩家在游戏里说话 → body 写 inbox → **L1 大脑把完整人设/状态/记忆 POST 到 :8788** → 认领 → 回单 → 游戏聊天框出现 `<DeepSeek> @玩家 …` |

**三个必踩的坑**（都实际踩到了）：

- **Git Bash 里 `curl -d "中文"` 会变 GBK** → 服务端解 JSON 直接 `400 bad json: 'utf-8' codec can't decode byte 0xd3`。
  正确姿势：`--data-binary @req.json`，文件用 UTF-8 写（`python -c` 里 `io.open(...,encoding='utf-8')`）。
  同理，往 worker 回中文也要走 UTF-8 文件喂 `deepsink_brain.py reply`。
- **人肉代答必掉单**：网关 `gateway.patience_ms=45000`，45 秒等不到回单就删请求 + 发兜底「（服务暂时繁忙，请稍后再试）」。
  AI 窗口只能在"被叫醒的那一拍"看日志，中间隔一次对话就超时 → **想稳定，必须上真模型（`backend: bridge → openai`），代码不用改**。
- **出生点在危险方块上 = 死亡循环**：机器人不躲不跑，死了原地重生。表现为聊天框每隔 ~30 秒一条
  `DeepSeek discovered the floor was lava`，`/data get entity DeepSeek` 里 `LastDeathLocation` 就是出生点。
  处置：`/tp DeepSeek <安全目标>` → `/spawnpoint DeepSeek`（把出生点设到当前位置）→
  `/data get entity DeepSeek Health` 验血（满 20.0f 即好）。

**坑位清单**：
- **「不断线」靠 supervisor**：`robot.py` 自己没有自愈能力，崩一次就整条链断（表现为"机器人不说话了"）。
  `supervisor.py` 每 2s 检查一次，死了等 3s 重拉，并在 `instance/robot/supervisor.json` 里刷新 pid 与重启次数
  （`status` 读的就是它）。它**不管大脑**——大脑要人判断，且两个大脑不能同时消费 inbox。
- **`brain.py watch` 等到一批就退出**：不续挂的话期间玩家说话没人接 → 用 `brain_watch_loop.sh` 自动续挂。
- `deepsink_brain.py watch` 认领一批就退出（设计给外层循环重挂），**没有外层循环 = 没人接单** → 用 `worker_loop.sh`。
- worker_loop.sh 自带**防僵尸**：认领到 age>60s 的旧请求直接放锁（客户端早超时了，接了也白发）。
- 大脑/服务掉线期间玩家发的召唤会**憋在 inbox**，链路恢复后 brain_llm 按顺序补排——表现为"几年前的提问突然有回复了"，属正常。
- 同一台机器**只跑一个 robot.py**：双实例会抢 cursor，表现为"吞对话"。

**探活**：
```bash
curl -m 3 -o /dev/null -w "%{http_code}\n" http://127.0.0.1:17890/health -H "X-Control-Token: $(cat instance/control_token)"  # 200=ControlMod 在
curl -m 3 -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8788/status                                                        # 200=DeepSink 在
```

### 8.9 怎么填 API key（2026-10-16）

**key 只存在两个地方，都不进 git**：环境变量 `MCROBOT_LLM_KEY`，或文件
`instance/robot/secrets.env`（`instance/` 已在 `.gitignore`）。**不要**写进 `identity.md`
或 `robot.json`（identity.md 只记「去哪个环境变量读」）。

**最省事的做法**：控制台 → 左栏「API key」输入框 → 填 → 保存。控制台会写进
`secrets.env` 并立刻生效，之后 `brain_llm.py` / `supervisor` 都会带上。

三种内置后端（控制台左栏下拉切换）：

| 后端 | endpoint | model | key 怎么来 |
|------|----------|-------|-----------|
| **DeepSink 本机伪 API**（默认） | `http://127.0.0.1:8788/v1` | `deepsink-chat` | 本机 DeepSink 官网 `http://127.0.0.1:8788/login` 注册后生成平台 key。**无 key 会返回 401**（`/v1/models` 空 key 实测 401），所以本机也要填 |
| **DeepSeek 官方** | `https://api.deepseek.com/v1` | `deepseek-chat` | 官方平台创建，`sk-` 开头 |
| **OpenAI 兼容（自定义）** | 自己填 | 自己填 | 按服务商（OpenAI / 硅基流动 / OpenRouter / 月之暗面…）要求填 |

也可以命令行给：

```bash
export MCROBOT_LLM_KEY=sk-xxxx          # Git Bash
setx MCROBOT_LLM_KEY sk-xxxx            # Windows 永久（重开终端生效）
```

**校验**：

```bash
python -m mcrobot.brain.llm_brain status        # 看 probe：ok：模型列表 / 需要 key / 不通
```

切到真 API 只需三步，**代码一行不动**：
1. 控制台改后端模板（或直接改 `identity.md` 的「后端」节）
2. 填 key
3. 重启大脑（控制台「启动 L1 大脑」，或 `python -m mcrobot.ops.supervisor start --with-api-brain`）

## 9. 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| `control_client.py` 连不上 | 客户端没起 / 端口没开 | 跑 `launch_client.py`；查 `instance/logs/latest.log`（**GBK 编码**） |
| 客户端「连接超时」 | 服务器没开 / 端口变了 / Forge 握手挂 | 等服务器就绪再连 |
| 指令回 `Unknown or incomplete command` | 没 OP，或少了前导 `/` | 确认 OP；`/command` 的 body 必须以 `/` 开头 |
| 操作被界面挡住 | 进服后没按 ESC | `control_client.py close` |
| 皮肤变默认 | 被 `/skin clear` 清掉 | `/skin set web slim <url>` 重设 |
| WE 指令无反应 | 没 OP / 选区未设 | `//size` 回读确认选区 |
| 改名后要重新注册 | yzt 按名字记账 | 正常；用新名字重登即可 |
| 机器人刷屏/复读 | 没开去重节流 | 检查 `robot.json.throttle`；日志出现 `dedup_skip`/`throttle_skip` 即生效 |
| 机器人不响应聊天 | 常驻循环没跑 / 游标卡住 | 跑 `mcrobot/body/loop.py`；看 `instance/robot/loop.out` 与 `logs/operations.jsonl` |
| **后端明明配了 MiMo，却还是「人肉代答/服务繁忙」** | 曾用 `supervisor` 起后端：它硬编码 `--backend bridge`，而 `deepsink_server.py` 是 `if backend: cfg["backend"]=backend`——**命令行覆盖配置文件**，把 openai 静默拉回 bridge | 2026-10-17 已修（`supervisor.py` 不再传 `--backend`）。自查：`python -m mcrobot.ops.supervisor start --with-deepsink` 后看 `instance/robot/deepsink.out` 首行应打印 `backend=openai` |
| 后端起来了但每次请求 500 | supervisor 没灌 `secrets.env`，子进程缺 `DEEPSINK_UPSTREAM_KEY` | 2026-10-17 已修（`cmd_start` 里先 `load_secrets()`）。现象是上游鉴权失败，不在日志里明说 |
| **闭环跑完说「做完了」，但东西没变** | 以前 verify 只看「命令返回 ok」，模型还会给 `{"ok": true}` 配一段「没验证」的批评 | 2026-10-17 已加硬闸：改世界任务没有成功 `block_probe` 就判失败。自查 `checkpoints/<task>.json` 的 `receipts` 里有没有 `block_probe` |
| 闭环某轮「0 次调用」 | `decide_parse_fail`：模型吐了非 JSON（XML / JSONL / 「服务繁忙」） | 看 `brain_llm.log` 的 `decide_parse_fail.raw`；三种格式现已兼容，busy 自动重试 2 次 |

### 9.1 工具层走 MCP（通用入口）

`mcrobot/tools/` 是 MCP 风格的工具注册表：每个工具用 **JSON Schema** 声明，
同时能产出 MCP 的 `tools/list` 格式和 OpenAI function calling 的 `tools` 格式。

**28 个内置工具**（`mcrobot/tools/builtin.py`）：

| 类别 | 工具 |
|------|------|
| 感知 | `get_state` `list_players` `get_inventory` `block_lookup` `block_probe` `block_at` `scan_region` `looking_at` `screenshot` `look` `review` |
| 移动（Baritone） | `goto` `goto_stop` `follow` |
| 动作 | `say` `run_command` `run_batch` |
| WorldEdit（危险，需白名单） | `worldedit_select` `worldedit_set` `worldedit_walls` `worldedit_hollow` `worldedit_replace` `worldedit_undo` |
| 技能库 | `skill_search` `skill_run` `skill_save` |
| 知识库 | `recall` `remember` |

> `worldedit_replace` 要两个方块（`block` 源 + `to` 目标），只给一个会被拒——
> 少一个参数会把整片选区填成同一种，这个口子不能开。

权限门控收在一处：**只读放行，`risk=dangerous` 的只认 `robot.json:auth.dangerous_allowed`**。
每次调用返回带 `action_id` 的结构化回执，便于把「指令 → 结果」关联起来。

**把自己挂成 MCP server**（任何 MCP 客户端都能指挥机器人）：

```bash
python -m mcrobot.tools.mcp_server       # JSON-RPC 2.0 over stdio
```

客户端里配成一个 stdio MCP server 即可（Claude Desktop / CodeBuddy / 各类 IDE 通用）。
MCP 客户端没有游戏内身份，默认以 `mcp` 身份调用 → **危险操作会被白名单挡下**；
要完整权限就把环境变量 `MCROBOT_MCP_ACTOR` 设成白名单里的玩家名。

### 9.1.1 腿与眼：Baritone + ControlMod 只读接口（2026-10-17 实装）

以前机器人只会原地施工：要它走到某处只能 `/tp`（像开挂，也不像真人）。现在补齐两层：

**腿 = Baritone**（`instance/mods/baritone-api-forge-1.10.1.jar`，1.20.1 专用版本）

- Baritone 走**聊天前缀**，不是原版命令：`#goto 27 -56 -191`、`#stop`、`#follow <玩家>`
- 工具：`goto(x,y,z)` / `goto_stop` / `follow(player)`，内部走 `cc.chat`，**不要用 `run_command`**
- `goto` 是异步的：返回后它还在走，要确认到位就再调 `get_state` 看坐标
- 实测：5 格距离 1 秒到；聊天前缀被客户端拦截，不会发到服务器

**眼 = ControlMod 新接口**（读法移植自 mcagent 的 `GameContext`，只保留纯客户端读）

| 接口 | 作用 | 说明 |
|---|---|---|
| `GET /blocks?x=&y=&z=` | 读单点方块 | `loaded=false` 表示区块没加载，**不能当空气** |
| `GET /blocks?x1=..&y1=..&z1=..&x2=..&y2=..&z2=..&limit=` | 读长方体（含端点） | 上限 4096 格；`truncated=true` 表示被截断 |
| `GET /looking` | 准星对准的方块/实体 | `type = block / entity / none` |
| `GET /screen.png?max=854` | 截当前画面，返回 PNG 原始字节 | 响应头带 `X-Image-Width/Height`、`X-Capture-Ms`；`max` 限 64~3840 |

对应工具：`block_at` / `scan_region` / `looking_at`。**毫秒级、不需要 OP**，比
`block_probe`（`/execute if block` 走聊天）快一个量级；`block_probe` 保留作兜底。

**截图**（`screenshot` 工具 / `GET /screen.png`）：客户端本地抓帧，存到
`instance/robot/shots/shot-*.png`，不含 HUD 和聊天框。实测 854×480 约 272 KB，
热身后 53–74 ms，首帧约 200 ms。窗口最小化或没有渲染帧时返回 504。

> **纯文字模型看不见这张图。** 它只适合留档给玩家、或给接了视觉的模型用；
> 不要让它拿截图判断「砌得对不对」——那仍然只能用 `scan_region` / `block_at`。

闭环硬闸已改成认这三种世界读取：改世界的任务，没有 `block_at` / `scan_region`
回执就判失败，不再信「命令返回 ok」。

**三个实现坑**：

1. 客户端 `Level.hasChunkAt()` 对远处会误报 `true`，必须用
   `mc.level.getChunkSource().hasChunk(x>>4, z>>4)`，否则未加载点返回 `void_air` 且
   `loaded=true`，验收墙时会把「没看见」当成「是空气」。
2. `scan_region` 一次十几格以上时，模型可能只读到前几行就断言不完整——它会自己分批
   再查（实测第 2 轮就是这样被 verify 打回的）。不要为此放宽 verify。
3. 截图必须在 `RenderLevelStageEvent.AFTER_LEVEL` 抓帧：双缓冲交换后 `glReadPixels`
   读到的是空缓冲。另外 `Screenshot.takeScreenshot()` **内部已经 `flipY()`**，
   再翻一次会得到上下颠倒的世界（第一次真机就是这样存了张倒图）。

**真机数据（2026-10-17，x=50~54 / y=48~50 / z=-191 砌 5×3 石墙）**：
3 轮 / 9 次调用 / 70 秒；第 1 轮 scan 全 air → 判失败重做，第 2 轮只读到 10 格 →
再判失败补全，第 3 轮 15/15 才通过；独立核对 15/15 stone。

### 9.1.2 mcagent 能拆什么、不能拆什么（2026-10-17 调研）

[keepermttl/mcagent](https://github.com/keepermttl/mcagent)：1.20.1 Forge / MIT / 18 工具。
**不能整体装来用**：`execute_commands` 是 `CommandExecutor.execute(ServerPlayer ...)`
+ SimpleChannel 自定义包，**服务端也必须装这个 mod**，还要求权限等级 4——别人的公服不可能满足。

| 部分 | 公服可用 | 处置 |
|---|---|---|
| `GameContext` 读类（player_state / inventory / entities / scan_blocks / looking_at） | ✅ 纯客户端 | **已移植**进 ControlMod（`WorldView` + `/blocks` + `/looking`） |
| `execute_commands` / recipe / structures / datapack | ❌ 需服务端装 | 不采用；改世界继续走 `connection.sendCommand`（原版协议，公服可用） |
| 18 工具 schema 与提示词策略 | — | 已借鉴（批量合并、失败止损、轮次上限 20） |

坑：它的 `send_chat_message` 只调 `displayClientMessage`（只在自己屏幕显示，**没发到服务器**）；
`scanBlocks` 只给方块统计、不给指定坐标。抄的时候别照单全收。

### 9.2 Voyager 式闭环（`robot.json:agentic`）

默认走一次性回复路径（模型回一段文本 → 解析 `[[cmd]]` → 交给身体异步执行）。
把 `robot.json:agentic.enabled` 改成 `true` 后走闭环：

```
perceive（环境快照）
   → decide（LLM 输出工具调用 JSON 数组）
   → act（同步执行，拿回执；一条失败即停）
   → verify（独立 critic 判成败 + 给批评）
   → 失败且未达 max_rounds → 带批评回到 decide
```

- `max_rounds` 默认 4（对齐 Voyager）；`action_budget` 默认 20（对齐 mcagent 工具轮次上限）
- 到上限或预算用尽就停手**不空转**，并把最后一轮批评记进日志
- **打开前必须确认大脑端点可用**，否则每轮都会干等到超时

#### 9.2.1 闭环真机首跑（2026-10-17，现在 `enabled=true`）

实测：让它砌一面 5×3 石墙 → **3 轮 / 5 次工具调用** → `block_probe` 回 `15/15` → 自己在聊天里说「做完了，3 轮 5 步」。
闲聊「在吗」11 秒（1 次 `say`）。开关改完**必须重启大脑**才生效（配置只在启动时读一次）。

先记住这五条，都是真机踩出来的：

1. **模型不会老老实实只吐 JSON**。同一句提示，它给过三种：正常 JSON 数组、
   `<tool_call><function=...><parameter=...></parameter></function></tool_call>`、
   「一行一个 JSON 对象」。解析器三种都认（`llm_policy._extract_*`）。
2. **上游会回「（服务暂时繁忙，请稍后再试）」**。以前被当成空计划，白烧一整轮（4 轮里废 2 轮）。
   现在 `decide` 解析不出动作会自动重试 2 次（间隔 2s）。
3. **「零回执」以前判成功**：解析失败 → 空计划 → verify 没回执 → 直接 `return True`。
   于是整条闭环**啥也没干却报成功**。现在零回执一律失败。
4. **模型会自相矛盾**：真机出现过 `{"ok": true}` 配一段「没有验证」的批评，而墙 0/15 一块没砌，
   玩家会听到「做完了」。所以加了**硬闸**：目标只要涉及改世界（砌/建/放/挖/墙/房/set/build…），
   回执里没有一次成功的 `block_probe` 就判失败——**不信模型自述，只认世界证据**。
5. **`worldedit_select` 的坐标必须带逗号**：`//pos1 30,48,-191`。
   写成空格会报 `Must have exactly 3 vector components`，整轮白跑。

**`block_probe` 是临时的眼睛**（`mcrobot/tools/builtin.py`）：对每个点发
`/execute if block <x> <y> <z> <block> run tellraw @s {"text":"<token>"}`，
再读聊天里有没有这个 token。`tellraw @s` 只有机器人自己看得见，不会把 token 刷到全服。
- 需要机器人是 **OP**；不是 OP 会全部报「不是该方块」
- 一次最多 24 个点（`action_budget` 是 20，注意别把预算吃光）
- 正解仍是给 ControlMod 加读方块原语（见 §10），这只是过渡

关掉闭环：`robot.json:agentic.enabled=false` + 重启大脑（回到一次性回复，快 10 秒内）。

### 9.3 技能库（Voyager 三件套之三，2026-10-16 实装）

前两件（多轮迭代提示 + 环境回执自检）已在 9.2；这一件解决**不复盘就永远重学**：

- **检索先于规划**：`perceive` 时按目标关键词查库，命中的技能摘要塞进观察里给决策器
- **只存做成过的**：`verify` 判 `ok` 之后，这一轮真正发出去的动作才入库（`learned-` 前缀）
- **按版本隔离**：库在 `version/<版本>/skills.jsonl`，换版本 = 换一套技能，不串味
- **带统计**：`uses/success` 记着，以后可以淘汰不好使的

预置建造模板（`mcrobot/skills/build.py`，装一次就一直在）：

```bash
python -m mcrobot.skills.library install     # 装 6 个预置技能
python -m mcrobot.skills.library search 砌墙  # 检索
python -m mcrobot.skills.library list         # 看成功率
python -m mcrobot.skills.library render build_wall pos1=0,0,0 pos2=10,4,0
```

| 技能 | 干什么 | 参数 |
|------|--------|------|
| `build_wall` | 选区砌一圈墙 | pos1 pos2 block |
| `build_room` | 空心房间（墙+地板+天花板） | pos1 pos2 block |
| `build_platform` | 铺平台/地板 | pos1 pos2 block |
| `replace_blocks` | 换选区里的方块 | pos1 pos2 block to |
| `clear_area` | 清空区域（填 air） | pos1 pos2 |
| `undo_last` | 撤回上一次 WE 操作 | — |

**规矩**：技能里不能套技能工具（防递归）；学到的技能**不会覆盖**预置模板；
`skill_run` 每一步照样过危险门控——没授权的步骤照样被拒，技能不是绕过白名单的后门。

### 9.6 知识层：把摸出来的事实写成本版本查表（2026-10-17 实装）

背景：玩过一次才知道的事（CFM 没有窗帘、垃圾篓真名 `rubbish_bin`、出生点在岩浆上会死亡循环）
以前只散在聊天记录和脑子里，换个会话就重新踩一遍。Voyager 的技能库记住的是**动作**，
这一层补另一半：记住**事实**。

两张表分工别混：

| 文件 | 模块 | 内容 | 怎么进上下文 |
|------|------|------|--------------|
| `memory/robot_memory.jsonl` | `mcrobot/memory.py` | 流水账：谁说了什么、我回了什么、临时想法 | 按时间取最近 N 条 |
| `memory/facts.jsonl` + `knowledge.md` | `mcrobot/knowledge.py` | 稳定事实：方块真名、指令坑、坐标、玩家偏好 | **按当前话题检索**，只注入命中的；查不到不注入 |

```bash
python -m mcrobot.knowledge remember "方块" "CFM 没有窗帘" --source "方块目录.md" --tags 家具
python -m mcrobot.knowledge search 家具
python -m mcrobot.knowledge list
python -m mcrobot.knowledge forget <id>
python -m mcrobot.knowledge consolidate     # facts.jsonl → knowledge.md 自动区
```

机器人自己也能记：工具 `remember`（出处必填）/ `recall`。
闭环每轮 `perceive` 按目标检索塞进 `observation.knowledge`；
聊天路径 `build_messages` 按**这一句**检索后拼进 system。

四条红线（别破）：
1. **出处必填**：`source` 空直接拒。只有工具回执 / 玩家原话 / 手册小节能当出处，模型猜的不记。
2. **自动区不手改**：`consolidate` 只替换 `AUTO:FACTS` 标记之间的内容，手写区一个字都不动。
3. **检索不到就不注入**：宁可不说，也别把无关事实塞进上下文（费 token 还误导）。
4. **冲突不自动删**：同一话题下矛盾的两条都留着，按出处和时间自己判断。

**失败自动沉淀成「教训」（2026-10-17 实装，对齐 mcagent 的反思）**：闭环跑完不是 ok 时，
`agent_loop._remember_lesson()` 把「目标 + 自检批评」写成一条 `topic=教训` 的事实，
**出处写死是这次闭环的 task_id**（形如 `闭环 oahnuy198-1760688000`）——模型不能凭空造记忆。
下次同类目标在 `perceive` 就能检索到，不用同一个坑踩两次。做成的路仍然只进技能库，不重复记。
任何记忆异常都吞掉：记忆是锦上添花，不能反过来影响任务结论。
单测把 `lessons_enabled=False` 关掉，免得每次跑失败用例都往版本知识表里写垃圾。

为什么不上向量库：事实量级几十~几百条，中文 2 字滑窗 + 关键词加权够用（与技能库共用
`mcrobot/textmatch.py`），零依赖、可解释、好单测。真到上千条再换。

### 9.7 视觉：截图 → 多模态模型 → 文字（2026-10-17 实装）

文本大脑能算坐标，但看不出「歪不歪、丑不丑、门洞留没留」。这一层补眼睛：
`look` 工具抓一张 → 发给多模态模型 → 把它的描述当工具回执交给文本大脑。

```bash
python -m mcrobot.vision check                     # 用 1×1 图探上游到底吃不吃图（不必先启用）
python -m mcrobot.vision shot "这面墙齐不齐"         # 现截一张再问（客户端要在游戏里）
python -m mcrobot.vision describe --file shot.png "描述画面"
```

- 配置：`robot.json:vision`（`enabled` / `endpoint` / `model` / `key_env` / `max_width` / `max_tokens`）。
  key 只从环境变量读：优先 `key_env` 指的变量，其次 `MCROBOT_VISION_KEY` / `MCROBOT_LLM_KEY`。
- 工具：`look`（第 27 个）。描述里明确写了「精确方块核对仍用 `block_at`/`scan_region`」——
  视觉会说错方块名，只能判外观，不能当验收证据。
- 实测（2026-10-17，MiMo `mimo-v2.6-flash`）：1×1 探活 5s；854×480 真截图 6~19s（冷启动慢，热身 6s）；
  能认出「绿顶白墙木柱的中式建筑、左侧深色方块与红色物体、右侧小木屋」，与人眼一致。
- **闭环实测（2026-10-17 14:33）**：目标「用 look 看一眼再用 say 告诉玩家」，大脑自己排出
  `look → say` 两步，`verdict=ok` / 2 轮 / 2 次调用 / 45s（其中 look 15.8s）。模型描述
  「绿顶白墙木柱、没装门窗、结构不完整」，与截图逐项对得上——**它没有编造，也没把方块名说死**。
  结论：`look` 可以放心交给决策器自己选，不用在代码里硬插「聊天前先截图」。
- **坑 1：DeepSink 会把图片丢掉**。`mock_api/deepsink_server.py:_text_of()` 把
  `messages.content` 拍平成文本，`image_url` 到不了上游，模型会「盲答」。所以 `vision.endpoint`
  **直连上游**（当前 MiMo），不复用 `llm_api`。以后修了网关再改回来。
- **坑 2：推理型模型把预算花在思考上**。`max_tokens=30` 时 `content` 为空、
  `reasoning_content` 一大堆（探活踩过）。默认给 600，报错会直接提示「调大 max_tokens」。
- **坑 3：慢**。一次 `look` 10~20 秒，别在闭环里连续调；一次任务看一两眼够了。
- **坑 4：全黑图不是建筑问题**。客户端刚起还没渲染完时截图全黑，模型会老实说「全黑」——这正是它没瞎编的证据。先 `bridge health` 看 `inGame`，再截。
- **坑 5：手动起 DeepSink 要先灌 key**。直接 `python deepsink_server.py serve` 会缺
  `DEEPSINK_UPSTREAM_KEY`，上游回 401、网关转成 500，大脑日志刷 `http_retry code=500`，
  一次任务白等 30 秒才判失败。正确姿势（或干脆让 supervisor 起）：
  ```bash
  set -a; . instance/robot/secrets.env; set +a; python ../mock_api/deepsink_server.py serve
  ```

#### 9.7.1 视觉验收：砌完自检怎么定义（2026-10-17 实装，`review` 工具）

**一句话：成败归世界回执管，视觉只产整改意见。** §9.2 的硬闸是「不信模型自述，只认世界证据」，
视觉验收不许动这根柱子——它是补在世界回执**之上**的一层，不是替代。

**分工表（定义的核心）**

| 问题 | 用什么 | 理由 |
|---|---|---|
| 砖放对没有、洞口通不通、尺寸够不够 | `block_at` / `scan_region` | 可数、可复现、免费 |
| 歪不歪、配色搭不搭、像不像房子、呆方盒程度 | `review` | 方块回执里没有「审美」这个字段 |
| 具体是哪个方块、坐标在哪、差几格 | 谁都不许猜 | 视觉会说错方块名（`look` 描述里已写死） |

规则：**能用方块回执验的，绝不用视觉。** 视觉只接回执结构上答不了的那一类。

**固定五项评分表**（不让模型自由发挥——答五个封闭问题比回答「好不好」稳得多）

| # | 项 | 判据 | 记分 |
|---|---|---|---|
| 1 | 轮廓完整 | 外轮廓没有缺口、破洞、悬空 | 是/否 |
| 2 | 边缘整齐 | 墙线基本平直，无明显凸出歪斜 | 是/否 |
| 3 | 配色协调 | 主色 ≤3 种，没有突兀色块 | 是/否 |
| 4 | 有层次 | 有立柱/出檐/门窗等细节，不是纯长方体 | 0-2 分 |
| 5 | 照片有效 | 能看清主体，不是全黑/被界面/天气糊住 | 是/否 |

- 第 1~4 项，模型的 note **必须引用画面里看得见的具体部位**（「屋檐下沿一条直线」「正面第二根白柱」）；
  写不出具体部位的一律判 false（第 4 项 0 分）——没看见就等于没有。这条是补过的：不加时
  模型对着一栋没装门窗的楼也直接 `pass`，一个字理由都不给。
- 第 5 项是**照片有效性闸，不是质量闸**：不通过就重拍，不进评分。这是唯一能让 `review`
  判「看不清」的地方，且失败的是照片不是房子。

**结论只有三种**（`mcrobot/vision.py:_parse_review` 强制归一）：

- `pass` 五项都过，没意见
- `fix` 1~2 条整改意见，`suggest` 必须具体到能用工具做（不许写「再修修」）
- `unclear` 照片无效或输出没法解析——**不产意见，也不判成败**

归一规则：第 5 项 false → 强制 unclear 且清空 issues；`fix` 但没有 issues → unclear；
`pass` 但存在 false/低分项 → unclear。**自相矛盾一律降级，绝不让它判成败。**

**反滥用条款**（已写进 `llm_policy.py` 的 decide/verify 提示词）：

- 视觉意见永远不能把 `ok` 判成 `fail`，也不能把 `fail` 洗成 `ok`；`verify` 只看世界读取
- 不许为了拍张好图而移动、等待、换角度
- 一次任务最多 1 次 `review`（实测 6~75 秒，方差大；74.5s 那次是冷启动）

**实测（2026-10-17 15:30，同一栋绿顶白墙未完工建筑）**

- 收紧证据规则前：直接 `pass`，零理由。
- 收紧后：`pass`，但逐项给了依据——「四根木立柱撑起屋檐形成门廊」「屋顶向前出檐盖过柱顶」
  「墙体中央留有门洞和两侧窗」。人眼核对：这些部位图里确实有（门窗洞有，门窗没装）。
- **由此定下评分表的边界**：五项问的是「结构好不好看」，**不问「完工了没有」**——「门装了没」
  属于功能项，而功能项恰好是 `scan_region` 能查的（门洞坐标是 air 还是 door）。
  想让机器人判「可交付」，得在世界回执里加功能检查，别指望视觉。

```bash
python -m mcrobot.vision review                       # 现截一张按评分表验收
python -m mcrobot.vision describe --file shot.png "…" # 自由提问（不验收）
```
